## 1. `form { display: flex }` перебив HTML-атрибут `hidden`

- **Що просив:** Task A — фільтр «Активні / Архів» і сховати форму створення, коли відкритий архів.
- **Що видав:** у `app/public/app.js` ставив `form.hidden = archived`, а в `app/public/style.css` лишив `form { display: flex; }`. Авторське правило перебиває UA-стиль атрибута `hidden` (`display: none`), тож форма лишалась видимою в архіві.
- **Як помітив:** у браузері, не зі скріншота. CDP `getComputedStyle(form).display` повернув `"flex"` при `form.hidden === true`. У дереві доступності поля «Заголовок» / «Додати» ще були, хоча фільтр «Архів» уже був `pressed`.
- **Як полагодив:** додано `form[hidden] { display: none; }` у `app/public/style.css`. Після цього `display` став `"none"`, поля зникли з a11y-дерева.
- **Чому агент так зробив (гіпотеза):** покладався на атрибут `hidden` як на достатню умову і не врахував, що `display` у таблиці стилів має вищий пріоритет.

## 2. Спочатку збирав `better-sqlite3@11` під Node 26, замість сумісної версії

- **Що просив:** «`npm test` падає, можливо `npm install` був з помилками».
- **Що видав:** діагноз «немає `better_sqlite3.node`» був правильний, але перша спроба — `prebuild-install` (404 на `node-v147-win32-x64` для v11.10.0), потім `node-gyp rebuild`. Компіляція впала на V8 Node 26: `GetPrototype` не є членом `v8::Object` у `binder.lzz`. Засіяні 9 тестів червоніли всі з однієї причини: `Could not locate the bindings file`.
- **Як помітив:** вивід `npm test` і лог MSBuild, не «тести бізнес-логіки».
- **Як полагодив:** у `app/package.json` залежність `better-sqlite3` з `^11.5.0` на `^13.0.3` (N-API, бінарник у пакеті). Після цього 9 тестів зелені без локальної збірки.
- **Чому агент так зробив (гіпотеза):** спочатку лікував симптом (заблоковані install-scripts у npm 12), а не несумісність ABI Node 26 × `better-sqlite3@11`. До мажорного бампа дійшов лише після failed compile.

## 3. Залишив фоновий `npm run dev` на 3080

- **Що просив:** перевірити UI в браузері (Task A), пізніше — «не вдається запустити `npm run dev`».
- **Що видав:** агент підняв `node src/server.js` у фоні (PID 2532). Користувач отримував `listen EADDRINUSE: address already in use :::3080`. Окремо один запуск з кореня репо дав `ENOENT` на `package.json` — скрипт живе в `app/`, не в корені.
- **Як помітив:** термінал користувача, `last_exit_code: 1`, той самий стек на `app.listen` у `src/server.js:8`.
- **Як полагодив:** зупинив `node` на 3080 (`taskkill /PID 2532 /F`) і знову запустив `cd app && npm run dev`.
- **Чому агент так зробив (гіпотеза):** зручно тримати сервер для браузерної перевірки, але не попередив і не прибрав процес після Task A/C. На Windows `npm run dev` з кореня виглядає як «зламаний скрипт», хоча це просто не та директорія.

## 4. `curl` у PowerShell — це `Invoke-WebRequest`

- **Що просив:** Task C — відтворити витік «зайди як один користувач і дістань нотатку іншого».
- **Що видав:** команду `curl -s -D - -H "x-user-id: 1" http://localhost:3080/api/notes/3`. PowerShell підмінив `curl` на `Invoke-WebRequest` і впав: `Missing an argument for parameter 'SessionVariable'`.
- **Як помітив:** одразу з виводу оболонки, до того як побачив тіло відповіді.
- **Як полагодив:** `curl.exe -s -i -H "x-user-id: 1" ...`. Тоді вже зафіксували витік: **200** і `{"id":3,"user_id":2,"title":"Приватна нотатка Тараса","body":"пароль від сейфа: 1234",...}`.
- **Чому агент так зробив (гіпотеза):** звичний Unix-`curl` без урахування alias у Windows PowerShell.

## Що агент зробив ДОБРЕ там, де я чекав проблем

- **Тест авторизації на читання написав і прогнав до фіксу.** `will not read someone else's note` був червоний: `expected 404 "Not Found", got 200 "OK"`. Це саме та вимога Task C, яку легко зімітувати «тестом, який завжди зелений».
- **Діру закрив умовою в SQL, не після `get`.** Було `WHERE id = ?` і ще й `user_id` у JSON. Стало `WHERE id = ? AND user_id = ?` плюс `publicNote` без `user_id` (`app/src/app.js`, `GET /api/notes/:id`).
- **Навмисну діру не «виправив заодно» в Task A/B.** `GET /api/notes/:id` лишився зламаним, доки не дійшли до Task C. `PATCH` уже мав `WHERE id = ? AND user_id = ?` — і для нього був крос-юзерний тест.
- **Не вигадав зайвих колонок** на кшталт `is_deleted`. Архів — одне поле `archived INTEGER NOT NULL DEFAULT 0`, для старого `notes.db` — `ALTER TABLE` лише якщо колонки немає.
- **UI перевіряв деревом доступності.** Кнопки — справжні `<button>` з видимим текстом і `aria-label`; розмір цілі 44×162 через `getBoundingClientRect`; порожній архів — `role="status"`, текст «Архівованих нотаток немає.»
