# Помилки й рішення AI — Завдання D

## 1. ❌ API повертав тільки активні нотатки

**Що просили:**
Додати функцію архівування з фільтром для перегляду архівованих нотаток.

**Що видав:**
```javascript
// НЕПРАВИЛЬНО - повертав тільки активні
app.get("/api/notes", (req, res) => {
  const rows = db
    .prepare("SELECT ... FROM notes WHERE user_id = ? AND archived = 0 ORDER BY id")
    .all(req.userId);
  res.json(rows);
});
```

**Як помітили:**
Тести впали під час імплементації фільтра-чекбокса. Фронтенд очікував отримати ВСІ нотатки (архівовані + активні), щоб фільтрувати їх на клієнті. Але API повертав тільки активні. Логіка фільтра зламалася.

**Як полагодили:**
Видалили умову `AND archived = 0`, щоб API повертав всі нотатки:
```javascript
// ПРАВИЛЬНО - повертає всі, фронтенд фільтрує
app.get("/api/notes", (req, res) => {
  const rows = db
    .prepare("SELECT ... FROM notes WHERE user_id = ? ORDER BY id")
    .all(req.userId);
  res.json(rows);
});
```

**Результат:** Тести пройшли, фільтр працює. Правильний розподіл відповідальності: API надає дані, фронтенд — логіку відображення.

## 2. ❌ Схема БД не збіглась із файлом бази даних

**Що просили:**
Додати колонку `archived` до таблиці `notes` для збереження стану.

**Що видав:**
Код змінили, але існуючий файл SQLite (`notes.db`) не мав нової колонки. При запуску сервера запити повертали помилку:
```
SqliteError: no such column: archived
  at Database.prepare (/path/to/better-sqlite3/lib/methods/wrappers.js:5:21)
  at app.js:34:8
```

**Як помітили:**
Тестування API через curl показало HTML сторінку помилки замість JSON. У логах сервера — помилка про відсутню колонку.

**Як полагодили:**
Видалили старий файл `notes.db`:
```bash
rm app/notes.db
```
Сервер автоматично пересоздав базу з новою схемою при перезавантаженні.

**Результат:** API тепер працює. Важливий урок: зміни схеми потребують міграції даних або пересоздання бази.

## 3. ❌ GET /api/notes/:id не перевіряв власника (діра авторизації)

**Що просили:**
Переконатись, що всі ендпоінти перевіряють чи користувач може доступити тільки свої нотатки (Завдання C2).

**Що видав:**
```javascript
// НЕПРАВИЛЬНО - перевіряє тільки існування, не власність
app.get("/api/notes/:id", (req, res) => {
  const note = db
    .prepare("SELECT ... FROM notes WHERE id = ?")
    .get(Number(req.params.id));
  if (!note) return res.status(404).json({ error: "not found" });
  res.json(note);
});
```

Користувач 2 (Тарас) міг запросити нотатку id=1 (власність користувача 1, Олі) і отримати її.

**Як помітили:**
Перевірка коду під час Завдання C2. Оригінальний код не мав `AND user_id = ?` у WHERE, це класична діра — «чи існує запис?» замість «чи ЦЕЙ користувач може доступити ЦЕЙ запис?»

**Як полагодили:**
Додали перевірку власності прямо в запит:
```javascript
// ПРАВИЛЬНО - перевіряє id та власність
app.get("/api/notes/:id", (req, res) => {
  const note = db
    .prepare("SELECT ... FROM notes WHERE id = ? AND user_id = ?")
    .get(Number(req.params.id), req.userId);
  if (!note) return res.status(404).json({ error: "not found" });
  res.json(note);
});
```

Додали тест, який ловить цю помилку:
```javascript
it("will not read someone else's note", async () => {
  await asTaras(request(app).get("/api/notes/1")).expect(404);
});
```

**Результат:** Діра закрита. Тест впадає, якщо хтось видалить перевірку `user_id`.

## 4. ✅ ДОБРЕ: Правильна авторизація на PATCH ендпоінті

**Що просили:**
Ендпоінт архівування що поважає власність (Завдання C1).

**Що видав:**
```javascript
app.patch("/api/notes/:id", (req, res) => {
  const archived = typeof req.body?.archived === "boolean" ? (req.body.archived ? 1 : 0) : undefined;
  if (archived === undefined) return res.status(400).json({ error: "archived field is required" });

  const info = db
    .prepare("UPDATE notes SET archived = ? WHERE id = ? AND user_id = ?")
    .run(archived, Number(req.params.id), req.userId);
  if (info.changes === 0) return res.status(404).json({ error: "not found" });
});
```

**Як помітили:**
Код був коректний з першої спроби — відразу включав `WHERE id = ? AND user_id = ?`.

**Результат:** Без переробок. Ендпоінт правильно:
- Валідує вхідні дані на сервері
- Перевіряє власність у запиті
- Повертає відповідні повідомлення про помилки
- Не видає зайвих полів

**Як помітили:**

**Результат:** Користувачі бачать доречне повідомлення залежно від фільтра. Помилок не було.
