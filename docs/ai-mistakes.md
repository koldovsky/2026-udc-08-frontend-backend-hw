## 2. Використав видалений Playwright API під час власної ж перевірки

- **Що просив:** сам собі поставив задачу (в рамках вимоги Task A
  «Перевірте в браузері… подивіться дерево доступності») — написав
  Playwright-скрипт, щоб зняти accessibility-снепшот живої сторінки й
  підтвердити, що кнопки архівування — справжні `<button>` з іменами.
- **Що видав:** у скрипті (`check_ui.mjs`, тимчасовий файл у скретчпаді)
  викликав `page.accessibility.snapshot({ interestingOnly: true })` —
  цей API прибрано з Playwright у версії, яку я щойно встановив (1.63.0).
  Скрипт впав одразу на першому запуску:
  ```
  TypeError: Cannot read properties of undefined (reading 'snapshot')
      at check_ui.mjs:19:43
  ```
- **Як помітив:** сам скрипт — стек-трейс при запуску `node check_ui.mjs`.
- **Як полагодив:** замінив на сучасний API —
  `await page.locator("body").ariaSnapshot()` — отримав коректний
  YAML-подібний ARIA-дерево з іменами всіх кнопок (`button "Архівувати
  нотатку «Список покупок»"` тощо).
- **Чому агент так зробив (гіпотеза):** знання про Playwright API
  застаріло відносно фактично встановленої версії; не звірив сигнатуру
  методу з актуальною документацією перед використанням.

## 3. Забув поле `archived` в одній з чотирьох відповідей — сам знайшов при написанні цього документа

- **Що просив:** Task B, явно — «Не віддавайте у відповіді зайвого» +
  імпліцитна вимога консистентності відповіді, коли з'являється нове поле
  схеми.
- **Що видав:** додав `archived` (через helper `asNote`) у відповіді
  `GET /api/notes`, `GET /api/notes/:id` і `PATCH /api/notes/:id/archive`,
  але **забув** у `POST /api/notes`
  (`app/src/app.js`, `SELECT id, title, body, created_at FROM notes WHERE id = ?`
  одразу після `INSERT`) — щойно створена нотатка приходила клієнту без
  поля `archived`, на відміну від усіх інших відповідей API.
- **Як помітив:** Агент знайшов сам, коли перечитував `app.js` рядок за
  рядком для підготовки інформації для цього документа.
- **Як полагодив:** додав `archived` у SELECT і обгорнув відповідь тим самим
  `asNote(...)`, що й інші три ендпоінти. 
- **Чому агент так зробив (гіпотеза):** редагував чотири місця вручну
  послідовно замість того, щоб винести спільний SELECT/маппінг в одну функцію
  і застосувати її одразу скрізь — класичне «забув один з N однакових
  випадків» через ручне дублювання.

## Що я перевіряв і воно виявилось чистим

- кожен `db.prepare(...)` виклик у `app.js` використовує `?` і передає значення
  окремими аргументами `.get()/.all()/.run()`.
- Playwright-сценарій:
  архівувала нотатку → **повний `page.reload()`** → стан лишився архівним →
  перемкнула фільтр → нотатка на місці. 
- Прямий `fetch` з `x-user-id: 1` на `PATCH /api/notes/3/archive` (чужа нотатка) — 404,
  запит з `x-user-id: 2` (справжній власник) — 200 з даними. Перевірено, що
  «відмова» — саме через власника, а не тому що маршрут узагалі не працює.
